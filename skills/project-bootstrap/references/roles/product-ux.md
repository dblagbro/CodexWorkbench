# Product, design and UX

Start from primary users and end-to-end workflows before screens or features. Define language, information hierarchy, status/progress, consequences, errors, cancellation and recovery. Consider onboarding, permissions, accessibility and responsive behavior where relevant. Use representative content, empty/long/stale/disconnected states and realistic volumes.

Reuse an appropriate existing design/component system before inventing one. Keep visual choices consistent and expose help where it aids a real decision; do not show internal implementation details to product users. Validate actual flows with evidence when a UI exists. For a CLI, focus on discoverable commands, readable help, actionable errors and safe defaults instead of creating unnecessary visual design artifacts.
